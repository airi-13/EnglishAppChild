# 設計（Cloudflare版）

出題の流れ・AIとプログラムの分担・障害時の動きは、Python版（`python-version/docs/design.md`）と同じです。この文書は、Cloudflare版での違いだけをまとめます。

## 構成
- 実行: Cloudflare Workers（`src/index.js`）。画面は同じWorkerが静的ファイル（`public/`）として配信。
- データ: D1（SQLite互換）。`src/schema.js` が定義の元で、初回アクセス時に自動作成される。
- AI: Gemini。`fetch` で呼び出し、再試行・タイムアウト・代替採点はPython版と同じ。

## D1に合わせた設計
1. **対話的なトランザクションがない** → 回答の保存は `batch()`（まとめて実行・途中で失敗したら全部取り消し）で行う。各文に「いま想定した段階のときだけ書く」条件を付け、**同時送信・二重送信でも記録が重複しない**（テストで確認）。
2. **無料枠は、読み取り・書き込みの行数に上限があり、超えるとクエリが失敗する** → 索引は最小限（書き込みが増えるため）。級・段ごとの問題数は `levels` に保存し、画面表示のたびに数えない。ログイン失敗だけを記録する。管理画面の集計は「直近N日」に限る。AI呼び出しの記録は、応答のあとにまとめて保存。
3. **無料プランのCPU時間は、1リクエスト10ミリ秒** → パスワードのハッシュは、回数を設定できる（既定3万回、約5ミリ秒）。生徒の登録は、1回に20人まで（画面側で5人ずつ送る）。CSVの取り込みは、1回250行まで（画面側で200行ずつ分け、先に全体を「確認だけ」してから書き込む）。回答ログの書き出しは、500件ずつ。
4. **サーバーを複数立てる構成のため、メモリ上の制限は使えない** → ログイン失敗のロックはD1に記録。AIの「1分あたりの回数制限」は、Workers側では管理しない（Geminiの429に対して、再試行と代替採点で対応）。
5. **最初の管理者** → コマンドではなく、画面から作る。`SETUP_TOKEN`（シークレット）を知っている人だけが、管理者が1人もいないときに限り作成できる。

## 変更したAPI（Python版との違い）
- `GET /api/status`、`POST /api/setup`（初期設定）
- `POST /api/admin/ai_check`（AI接続チェック）
- `POST /api/admin/questions/import` に `dry_run`, `row_offset`
- `GET /api/admin/export/attempts?after_id=&limit=`（CSVではなく、分割したJSON）
- 管理者の集計APIに `?days=`
