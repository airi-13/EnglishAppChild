## 確認した主な内容
**出題フロー**
- 本文 → 間違えた問題だけ空欄補充 → それでも間違えた問題に解説＋確認テスト → まとめ、の全経路
- 全問一発正解（AI呼び出し0回）、空欄で正解、確認テストまで進む、の各経路
- 途中送信（未回答あり）は拒否され「No.○にも答えてね」と返る／文字数超過の拒否
- 続きの5問、級の最後（40問目）で次の級・段へ進む、最後の段で終了表示
- 途中で閉じても同じ生徒は再開できる／やめる／二重送信は409で記録が重複しない
- 本文の段階で**正解がブラウザに送られない**こと（正解の和文がレスポンスに含まれない）

**セットアップ・接続チェック・公開スクリプト（本物のGoogle・GitHubには接続せず、テスト用サーバーとローカルのGitリポジトリで確認）**
- `setup.py`: キーなし→簡易モード、再実行しても壊れない、短い管理者パスワードの拒否、キーあり→接続チェックまで通る
- `check_gemini.py`: 成功、キー形式の不備、無効キー(400)、API未有効(403)、AQ.キーの401(`ACCESS_TOKEN_TYPE_UNSUPPORTED`)、通信不可、モデル名が一覧にない場合の自動修正。**キーは画面にもURLにも出ない**（ヘッダーで送信）
- `publish_github.py`: `.env`・DBを除いて公開、履歴にキーが残らない、ソースにキーがあれば公開を中止、認証失敗時にトークンが出力・`.git/config`に残らない、プロジェクト自身に秘密情報が無い
- テストの過程で、`.env.example` の「`GEMINI_API_KEY=   # 説明`」の説明文がキーとして読まれる不具合を見つけ、修正済み

**AI連携（本物のGoogleには接続せず、Gemini互換のテスト用サーバーで確認）**
- リクエストの形（モデル名・キーのヘッダー・JSON出力指定）、応答（JSON／コードブロック付き）の解析
- 429/503での再試行（Retry-After尊重）、500継続時は2回の再試行で打ち切り、400/401/403/404は再試行しない
- タイムアウト、接続拒否、キー未設定、JSON不正、判定値の不正、一部の項目だけ欠けた応答 → いずれも**代替採点**で継続
- AIが全面停止しても、本文→空欄→解説→確認テスト→完了まで通ること／復旧後は通常採点に戻ること
- 生徒のID・表示名・パスワード・APIキーが**AIへの送信内容に含まれない**こと
- 生徒の回答が「指示」ではなくJSONのデータとして渡されること

**セキュリティ・権限**
- 誤パスワード、5回失敗でロック、生徒による管理APIの拒否、未ログインの拒否
- 非JSON・別オリジンからのPOSTを拒否（CSRF対策）
- パスワードはハッシュ保存／再発行で既存ログインが無効／停止した生徒はログイン不可
- 他の生徒のセットを閲覧・送信・中止できない
- 入力した `<img onerror=...>` が実行されず、文字として表示される（一覧・結果画面とも）
- CSV出力の数式（`=HYPERLINK(...)`）がエスケープされる／セキュリティヘッダー（CSP等）

**管理者機能・集計**
- 生徒の一括登録（パスワード自動発行・1度だけ表示）、不正ID・重複IDのエラー
- 正答率（全体・生徒別・級別）、よく間違える問題、間違いの多い問題ランキング、日別の利用、AI成功率、代替採点の回数が、記録と**一致**
- 問題CSVの取り込み（不備があれば1問も入れず行番号つきで報告／上書き）、1,600問（40級・段×40問）の取り込み
- 回答ログのCSVダウンロード

## Macの標準Python（3.9）への対応
- 実機（Mac / Python 3.9.6）で、パスワード保存に使っていた `hashlib.scrypt` が存在せず起動できない不具合が見つかったため、どの環境でも使える PBKDF2-HMAC-SHA256（60万回）に変更。
- 再発防止として、`hashlib.scrypt` を取り除いた状態で全テスト（57件）を実行して合格を確認。全ソースが Python 3.9 の文法で解釈できることも確認。
- ログイン1回のハッシュ計算は約0.18秒。40人が**同時に**ログインした場合、最後の人は数秒待つ（その後の操作は0.1秒前後）。

## 負荷テストの数字（参考）
- 最新（40人×2セット、PBKDF2）: エラー0、80/80セット完了、重複記録0、DB整合性OK。応答時間の95%点は7.1秒（同時ログインの集中による。操作の中央値は0.10秒）。
- 再実施（40人×2セット）: エラー0、80/80セット完了、95%点 1.9秒。
- 60人同時 × 2セット: 620リクエスト、AI呼び出し160件（すべて成功）、所要12.5秒。
- 応答時間: 中央値 0.22秒／95%点 4.8秒／最大 7.9秒。遅い側は、同時ログインのパスワードハッシュ計算（この環境はCPU 1コア）と、モックAIの遅延0.3秒×複数回によるもの。

## 確認できていないこと（正直な注意）
1. **本物のGeminiとの通信**：この環境ではインターネットに接続できず、APIキーもないため、実際のGoogleには接続していません。通信の形式はGeminiの公開仕様に沿って実装し、互換のテスト用サーバーで確認しました。**モデル名（既定 `gemini-flash-latest`）が有効かは、キーを設定して一度動かして確認してください。**
2. **AIの日本語の質・判定の正確さ**：テストのAIは文字列の類似度で判定する簡易モックです。実際の解説の分かりやすさ、言い換え回答の判定精度は、実キーで確認が必要です（`prompts.py` で調整できます）。
3. **gunicorn・HTTPS・リバースプロキシ**での動作：この環境に gunicorn が無く、開発用サーバーで確認しました。READMEの手順で本番構成にする場合は、起動確認をしてください。
4. **サンプル問題**はテンプレートで機械的に作った練習用です。実際の教材はCSVで取り込んでください。
5. 実機の端末（iPad・各種スマホ・日本語入力の挙動）での確認は未実施です（Chromiumの375px幅のみ）。
